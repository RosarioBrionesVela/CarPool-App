# CarPool – Mobile Application

## 1. Project Description

CarPool is a mobile application that connects drivers and passengers who travel to the same destination. The application helps people share rides and travel costs in a simple and safe way.

## 2. Project Vision

Our vision is to create an accessible and safe platform that makes shared transportation easier and helps people save money.

## 4. Project Objectives

* Create a mobile application prototype.
* Connect drivers with passengers.
* Allow users to share travel expenses.

## 5. Tools

* Notion: Project management and documentation.

## 6. Workflow Rules

1. Every task must have an assigned person.
2. All members must keep their work organized.
3. Changes must be submitted through Pull Requests.
4. At least one teammate must review each Pull Request.
5. Changes must be approved before being merged into the main branch.
6. All members must communicate their progress.

## 7. Change Approval Process

* Create a branch for your task.
* Make and save your changes.
* Submit a Pull Request.
* Ask a teammate to review the changes.
* Make corrections if necessary.
* Merge the changes after approval.
  
## 8. Branch Rules

- The main branch contains the approved project files.
- Each member must create a separate branch for their tasks.
- Branch names must describe the work.
- Members must use Pull Requests to submit changes.
- Another team member must review the changes before merging.
- Only approved changes can be added to the main branch.
  
## 9. Communication

The team will use Notion to organize tasks and Discord to communicate.

## 10. Branching Strategy

The project uses GitHub branches to organize development and protect the main version of the application.

- **main:** The main branch for approved changes.
- **design-screens:** The branch used for the application's screen design work.
- **Feature branches:** Additional branches can be created for specific tasks or features.

Team members should work on their assigned branches and submit a Pull Request before merging changes into `main`.

## 11. Pull Request and Issue Templates

Pull Requests are used to propose changes and request feedback from teammates. Each Pull Request should describe the changes, explain how they were checked, and identify any related task.

Issues are used to register tasks, improvements, and bugs. Each Issue should include a clear description and the expected result.

The project uses templates to help team members provide consistent information when creating Pull Requests and Issues.

## 12. Branch Protection and Review Policy

The team aims to protect the `main` branch by requiring changes to be submitted through Pull Requests and reviewed before merging.

At least one teammate should approve each Pull Request before it is merged. Branch protection settings are used to enforce these requirements when they are available and configured in the repository.

## 13. Automation

GitHub Actions runs an automated documentation validation workflow. It checks whether required sections are present in the project documentation.

The team can review the workflow results in the GitHub Actions tab to identify missing information and verify whether the documentation check passes.
